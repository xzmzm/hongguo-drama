# USB 手机签名开发验证记录（2026-11-16）

此前开发已完成手机端签名服务和真实播放模型请求验证，桌面接入尚未开始。本轮完成桌面代码接入；这是开发验证，不是正式发行或全平台验收。

## 使用方式和边界

在「设置 → 播放与缓存」开启「USB 手机签名」并保存，后台设置名为 `usb_signer`，默认关闭。需要 USB 连接已授权调试的 Android 手机，并预先安装配套的 `com.sign.oracle` 签名服务。脱敏后的辅助程序包装源码与构建步骤见 [tools/sign-oracle](../tools/sign-oracle/README.md)。SDK 原生库、许可证、实际配置与签名密钥仍由使用者本机提供，不加入本项目源码或发行包；桌面不自动安装 APK。

桌面进程在实际需要播放模型时检查本机 `127.0.0.1:8762`；服务未就绪时通过 adb 选择唯一 USB 实机、启动已安装的服务并建立端口转发。已有转发属于其他设备或不同端口时停止，不覆盖。adb 可来自 PATH、`ANDROID_SDK_ROOT`／`ANDROID_HOME`，也可用 `HONGGUO_ADB_PATH` 指定可执行文件路径。

关闭设置时不启动 adb，也不连接签名服务；已经启动的手机服务和转发不会因关闭此设置而被强制停止。正在复用的有效媒体缓存保留。没有配置此桥接的服务端／Docker 入口仍默认关闭。

服务启动最多等待 8 秒，单次签名最多等待 2 秒，均在原有播放模型请求预算内。准备服务后才构造带时间戳的最终请求；每次原有重试重新签名。签名输入是最终 URL 和实际发送的 gzip 正文字节，替换请求中的同名签名头，不混用旧签名；只接受预期签名头，不接受手机回复中的 Cookie、Authorization 或任意网络配置。

手机断开、服务缺失、签名不全或超时会给出「USB 手机签名不可用」提示，保留取消行为，不暗中发送未签名请求。此接入只覆盖原有红果 App 播放模型取源，搜索、账号、分集锁定、身份、时长、尺寸、媒体地址和解密校验保持原有边界。

## 限制

此前集成实测只验证当时 Windows 开发构建和已连接的 Android 手机，不外推到其他手机、macOS、Linux、Docker 或正式安装包。手机必须保持连接，签名服务依赖当前手机端库与运行环境，上游更新后可能需要重新适配。样本成功不等于所有上游拒绝均已根治。
